# Архитектура

Расширение состоит из двух изолированных частей, которые общаются через `postMessage`.

```
Страница lichess.org
├── content/lichess.js  (контент-скрипт)
│   ├── читает ходы партии из DOM (SAN: "e4", "Nf3", …)
│   ├── создаёт панель: заголовок + iframe с panel/panel.html
│   ├── рисует стрелки поверх доски (SVG внутри cg-container)
│   └── postMessage ──► панель:  { type: 'game',  moves, orientation, myColor, … }
│                                { type: 'scale', scale }
└── panel/panel.html   (iframe, origin расширения)
    ├── panel.js     состояние, обработка сообщений, вся отрисовка HTML
    ├── engine.js    Stockfish в Web Worker, протокол UCI
    ├── explain.js   объяснение ходов «человеческим языком»
    ├── coach.js     оценка качества ходов, вопросы перед ходом, итоги
    ├── lessons.js   курс уроков (статические тексты)
    ├── board.js     мини-доска (SVG) для разбора
    ├── store.js     сохранение партий в chrome.storage.local
    └── postMessage ──► контент-скрипт: { type: 'arrows', shapes }
                                        { type: 'status', text }
                                        { type: 'ready' }
```

Почему панель в iframe: контент-скрипт живёт в origin lichess.org, а движку Stockfish нужен
Web Worker и WebAssembly из origin расширения. Iframe даёт панели собственный origin, где это
разрешено политикой безопасности (`wasm-unsafe-eval` в манифесте).

## Поток данных при ходе

1. lichess дорисовывает ход в список ходов, срабатывает `MutationObserver`.
2. `readGame()` собирает массив SAN-ходов, ориентацию доски, цвет игрока, тип партии, часы.
3. Панель получает сообщение `game`, восстанавливает позицию через chess.js и запускает анализ.
4. Пока движок считает, приходят события `info` с оценкой и линиями. Панель перерисовывается.
5. Когда позиция сменилась, предыдущий анализ используется для оценки только что сыгранного хода:
   сравниваются оценка до хода (лучшая линия) и после (оценка новой позиции с обратным знаком).
   Разница в процентах шансов на победу даёт категорию: лучший ход, неточность, ошибка, грубая ошибка.
6. Результат сохраняется в `state.records` и в `chrome.storage.local`.

## Ключевые соглашения

**Оценки движка.** Stockfish возвращает оценку с точки зрения стороны, которая ходит.
Внутри панели оценки хранятся в этом же виде, а для показа пользователю переводятся в точку
зрения белых функцией `negate()`. Функция `winPct()` переводит сантипешки в проценты шансов
на победу, именно по ней считается качество хода.

**Идентификаторы запросов.** Движок один, а запросов много (позиция, угроза соперника, разбор).
Каждый запрос получает номер (`state.reqId`, `review.reqId`); ответы с устаревшим номером
отбрасываются. `engine.analyze()` сам прерывает предыдущий поиск командой `stop`.

**Теги и уроки.** Каждая причина в объяснении помечена тегом (`material`, `tactics-fork`,
`prophylaxis`, …). Теги связаны с уроками через `TAG_TO_LESSON` в `lessons.js`, поэтому
из любого объяснения можно перейти к теории.

**Хранение.** Партия сохраняется целиком (`game:<id>`), плюс краткий индекс (`gameIndex`)
для списка истории. Запись отложена на 800 мс, чтобы не писать на каждый ход.

## Тесты

`npm test` запускает юнит-тесты на встроенном тест-раннере Node: проверяются объяснения ходов
(`test/explain.test.js`) и тренерская логика (`test/coach.test.js`). Зависимостей не требуется.

`npm run e2e` запускает сквозной тест: поднимает Chromium с установленным расширением и
подставляет страницу с разметкой lichess. Требует установленного Playwright (`npm i -D playwright`)
и браузера; в обычной разработке не обязателен.
